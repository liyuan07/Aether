# Rust 业务核心重构记录

目标是迁移全部平台无关业务核心，同时保留原生 Swift 页面、交互和 macOS 平台适配。整个目标仍在进行；建立静态库并不等于全应用重构完成，语言替换本身也不保证资源下降。

## 剩余迁移

- 剪贴板：完整记录所有权、资源引用事务及原生 Store 的剩余装配/事务决策继续审计；归档编解码和分组决策已有 Rust 接入（见后文），剪贴板读取、图片/RTF 数据处理与 Calendar 继续通过平台接口。
- 快捷操作：规则配置/导入导出事务、窗口布局/应用动作会话中的剩余决策；默认规则升级及执行资格已接入，AX、Carbon、事件 tap 和应用启动仍通过平台接口。
- Prompt：继续评估展示 DTO 桥接和历史快照分配；原生编辑器、URLSession、本机凭证写入回滚协调需维持行为。
- 端口：已接入生命周期、解码、归属、能量与历史核心，继续审计原生聚合适配中是否仍有未迁移决策；IOKit/SMC 适配、图表与硬件验收保留。
- 共享层：配置、迁移事务和路由规则；应用生命周期、偏好域、登录项保留 macOS 适配。
- 全功能正式安装验收、固定工作负载 CPU/内存/能耗测量与目标评估。

## 验证原则

使用隔离偏好域和合成数据。保留迁移前独立参照或现有明确预期的回归测试；不把两条同调 Rust 的路径互相比对当作差异验证。数据格式变更另设可重试迁移，未知版本和损坏数据不能被空列表覆盖。当前阶段不改变数据格式。

冷搜索包含归一化与索引构建，缓存评分衡量重复查询，两者分开记录。未完成可比整机测量之前，不宣称整体开销已显著下降。已安装 Swift 版本的 RSS 在编译压力下明显波动，单次 RSS 和 ps 的衰减 CPU 读数不能作为最终性能结论。

## 首批迁移测量（2026-10-06，本机 arm64，Release）

| 合成工作负载 | 原 Swift | 当前 Rust 接入 | 限制 |
| --- | --- | --- | --- |
| 5,000 条冷索引搜索 | 41.18 ms | 23.95 ms | 各一次，跨进程，包含归一化/索引/排名 |
| 10,500 条冷索引搜索 | 85.59 ms | 49.81 ms | 同上 |
| 20,000 条冷索引搜索 | 165.92 ms | 95.03 ms | 同上，约降低 43% |
| 20,000 段、6 查询、5 轮缓存评分 | 1,622.66 ms | 27.96 ms | 同进程、600,000 次，仅评分，不含排序、界面或数据读取 |

缓存评分累计分数一致；独立原 Swift 参照、Unicode/边界样例及 2,000 组生成样例均通过。以上是首轮局部性能数据，不能推导全应用内存或能耗下降。原始日志位于 `.build/logs/swift-baseline-search.log`、`.build/logs/rust-search-comparison.log`，不含真实剪贴板正文。

## 第二批迁移验证

快捷键策略和窗口几何的计算已通过 C ABI 接入 Rust。`RustShortcutParityTests` 在 200 组各 40 条合成规则、指定映射环与前置路径、标准菜单组合中比较原 Swift 实现；`RustGeometryParityTests` 比较 1,000 组生成的窗口、多屏、尺寸和碰撞场景以及同面积同距离屏幕的优先顺序。原有快捷键、窗口移动会话及截止时间测试继续通过，全部 Swift 回归与 Rust 单测通过。

本批没有修改界面或 AX 操作流程。生成数据回归不替代真实辅助功能权限、应用响应或外接屏验收；本批不宣称额外的整机性能收益。后续存储迁移将继续保留当前版本封装、损坏文件保护与原子替换语义。

## 第三批迁移验证

备忘录记录状态、增删、排序、版本检查和持久化已在 Rust 中执行，Swift 的模型负责发布原生展示快照。新增/删除成功写入后才提交核心状态，失败保留已显示内容；明确重载修复后的文件才能解除损坏/新版本写入阻止。排序索引只在数据变化时生成，并复用原生记录以避免重复复制正文。文件仍为 schemaVersion=1、payload 数组，日期保持毫秒时间戳，未知旧字段继续忽略。

通用 Rust 文件层接入 Prompt、常用剪贴板、快捷键规则/偏好和剪贴板归档；这些功能的领域规则及原生 DTO 版本解码尚未全部迁入。私有文件保留 0700/0600 权限及符号链接拒绝，Prompt 保留写入同步；一般配置保持原有默认权限策略。读取缓冲区通过 Data 的自定义析构接管所有权，通过 Data(bytesNoCopy:) 移交读取缓冲区，避免适配层主动创建第二份字节数组。

隔离测试覆盖空/小/大缓冲区寿命、中文文件名、私有权限、符号链接、原子替换失败的原文件保护/临时文件清理，以及备忘录排序、增删、损坏/未知版本、外部更新与修复重试。既有 Prompt 凭证回滚、未来格式与损坏保护、常用内容和快捷键读写测试继续通过。

Rust JSON 依赖固定为 serde 1.0.228 / serde_json 1.0.145，所有传递依赖在 Cargo.lock 中锁定；安装前校验应用内所有依赖许可证与实际锁定源码一致。尚未宣称本批带来整机 CPU/内存下降。

## 第四批迁移验证

Prompt 的 Chat Completions 请求体、HTTP 错误映射、响应结构/拒绝/截断检查和接口路径策略迁入 Rust。URLComponents 保留原生 URL 解析，URLSession 保留禁止重定向、超时和取消；API Key 仍只经过原生请求头与钥匙串，Rust 不接收 Key。请求代际状态机拒绝取消后、旧请求和重复完成；历史操作返回索引，locale 匹配保持 Foundation 原有语义。

配置和历史的 schemaVersion=1 校验、类型验证、损坏/未来格式写入阻止及原子同步写入由 Rust 持有。Swift 仅桥接原生 DTO 和错误文案。Prompt Date 继续使用 Codable 的参考日期秒值，备忘录仍使用原有毫秒格式，二者不混用。通用版本封装与 UUID 校验复用于备忘录，相关全部回归通过。

`RustPromptParityTests` 保留迁移前独立 Swift 响应解码器，对照 504 组 Unicode/NUL、内容分段、结束原因、拒绝及第二候选畸形组合；100 组历史排序/删除/保留/locale 筛选和 1,000 轮请求代际检查通过。原生版本一文件、浮点日期精度、整数的十进制/指数表示、权限和畸形载荷原文件保护测试通过。全部 Swift 测试和 Rust 单测通过；本批未改动页面源文件，也不将模拟网络回归视为真实模型服务、钥匙串或交互验收。

## 第五批迁移验证

常用剪贴板 quick-maps.json 的版本验证、记录状态、重复规则、默认名称、增删改与撤销持久化事务在 Rust 中执行。仍使用 schemaVersion=1、collections 字段和毫秒日期；写入前检查外部文件，损坏/未来格式/符号链接不能被覆盖，明确重载修复后才解除阻止。分组名称的当前 locale 折叠、标题的 Swift 字符串规范等价和搜索字符串匹配保留 Foundation 原生语义，Rust 使用这些比较输入执行领域策略和排名/分组。

Rust 记录通过 Arc 共享未修改分组的条目数组和条目正文，修改时才复制对应数组；写入成功后返回单个分组的展示补丁，Swift 发布该补丁，不通过桥接重复编解码全部分组。失败不替换核心或展示状态。页面源文件未修改。

`RustQuickClipboardParityTests` 保留迁移前独立 Swift 模型、存储和搜索排名实现；1,600 组 Unicode、NUL、中文、大小写、宽度、组合字符与同时间排序搜索，以及 100 轮编辑/重复校验/删除/撤销序列通过。原生版本一文件、权限、未来文件在载荷变化时保护、修复重载和符号链接测试通过。Rust 单测及全部 Swift 回归通过。

本机 arm64 Release 合成基准：50 分组、1,000 条含长正文的记录，9 次分组改名并核对全部结果一致，旧 Swift 业务/DTO 存储中位 11.17 ms，Rust 接入中位 3.19 ms，约降低 71%。两者使用同一通用文件层；包含外部文件检查、原子写入和展示更新，不含页面渲染。原始日志 `.build/logs/rust-quick-mutation-benchmark.log`。该结果不代表全应用内存或能耗结论。

Prompt 页的正式安装验收发现原生同步钥匙串读取等待阻塞主线程；堆栈定位到 SecItemCopyMatching，系统 SecurityAgent 窗口不允许 Computer Use 工具访问。该权限交互尚未完成，后续需保留凭证安全边界并处理平台等待，不能以模拟网络或编译检查代替验收。

## 第六批迁移验证

历史插入、乱序捕获与较新重复保护、重复 UUID 移除、保护项裁剪、图片/富文本清理标记迁入 Rust 索引计划。裁剪使用一次逆序扫描和压缩，替代反复从数组中间删除；不需裁剪时由核心的边界判断直接复用原生数组，未插入的晚到重复也复用原生历史。只借用 UUID/时间/类型/比较标志，不向该规划 ABI 传入剪贴板正文。

捕获内容身份、持久分组身份、收藏转移、分类、稳定 UUID 去重、有效/过期/数量筛选在 Rust 中执行。Swift String/可选数组/Data 比较保持原生规范等价，核心指定需要的比较字段并在必要时要求原生读取 RTF，类型不同和文本不同不会触发多余富文本读取。图片捕获身份使用可用的内容 hash、缺失时回退文件名，而分组身份继续采用原来的持久字段；两种身份规则不混同。Calendar 日历日期、文件访问与异步取消仍通过原生桥接。

`RustClipboardHistoryParityTests` 保留迁移前独立 Swift 插入/裁剪/内容/收藏/分类参照；1,500 组插入及裁剪、3,600 对全部内容类型/可选字段比较、100 组维护和 300 组收藏转移，以及持久分组与捕获身份区别通过。生成记录包含重复 UUID、乱序/相同时间、零上限、保护条目、NUL 与规范等价 Unicode，全部使用合成内存数据，不访问真实负载目录。现有 Swift 全部回归与 Rust 单测通过。

本机 arm64 Release，5,000 条历史、后 2,500 条受保护、上限 2,500 的合成重裁剪，7 轮相同结果对照：原 Swift 中位 219.29 ms，Rust 规划及原生快照桥接 0.237 ms。该工作负载用于验证消除反复扫描/移动的复杂度，不能当作日常所有操作或整机占用的收益。日志 `.build/logs/rust-history-trim-benchmark.log`。

跨功能共享的字节借用与 UUID ABI 类型已移至 `abi.rs`，剪贴板与 Prompt 之间不形成业务模块依赖。完整历史记录所有权、归档编解码及调度状态仍需迁移；整个目标保持进行中。正式安装仍受系统钥匙串提示的同步等待阻塞，未将该平台验收标为完成。

## 第七批迁移验证

剪贴板 changeCount 的捕获/最多四次失败/确认/自身写入确认状态、历史修订计数与维护代际、24 小时维护触发，以及归档写入合并和清理标志转入 Rust 值状态机。Swift 保留系统剪贴板读取、Date 时间输入、Task 取消与 DispatchQueue 执行，120 ms 合并时间和现有接口未改。自身写入仅更新已观察计数，与成功捕获后清空待重试状态的路径保持原有区别。

未引用图片/RTF 文件选择由 Rust 以借用文件名集合执行。原生文件名先做 canonical composition，保持 Swift String 的规范等价，大小写和宽度不额外折叠；原生枚举/删除仍在归档原子写入成功后执行。归档失败不触发任何清理。写入器可注入目录，使集成测试完全隔离，应用默认路径与文件格式不变。

`RustClipboardScheduleTests` 使用迁移前独立状态参照对照 30,000 次捕获事件、10,000 次写入合并、整数边界/计数器回绕、原生 Date 的每日边界及 Unicode 资源名。`ClipboardPersistenceTests` 实际验证延迟落盘、合并清理标志、history/pinned/groups 引用保留、NFC/NFD 文件名保留、失败替换原文件与负载保护；全部 Swift 回归和 Rust 单测通过。

本批不宣称额外的整机性能收益。归档记录所有权和完整格式编解码仍需迁移，原生排队快照仍为 ClipboardArchive；源身份数组对照、分组创建生命周期与平台任务装配也需继续评估。系统钥匙串提示尚未解除，正式安装/真实页面验收仍未完成。

## 第八批迁移验证

剪贴板归档旧格式的类型/UUID/日期/Base64 校验、读取缓冲区和覆盖阻止状态接入 Rust。读取失败或保存前发现外部损坏后，后续保存不能覆盖原文件，也不会删除负载；修复文件并明确重载后才能恢复。无版本 history/pinnedItems/groups 格式、缺省字段和原生 DTO 展示行为保持不变；缺省 UUID/日期/预览仍由原生生成，加载本身不重写旧文件。

校验器借用未转义字符串，转义字段才解码分配。正常解析不创建通用 JSON 树；重复字段的异常兼容路径按 Foundation 的首次出现值规整，原生允许的额外 Base64 padding 和最多 512 层容器边界亦有对照。`RustClipboardArchiveTests` 比较原生 DTO 的字段接受矩阵、重复字段、未知嵌套元数据；`ClipboardPersistenceTests` 验证损坏文件/图片负载保护与明确修复重载。测试完全使用合成数据与隔离目录。

本批只迁移格式校验与持久化保护，不宣称完整归档记录所有权/原生 DTO 编解码已迁移，也不宣称整机资源收益。正式安装和页面验收仍需解除先前系统钥匙串等待；整个目标继续进行。

## 第九批迁移验证

USB-C/雷雳连接生命周期的记录状态、向前推进、完成移除、断开/已解析清理、3 秒静默超时和 6 秒持续提示上限迁入 Rust。时钟回拨时重新建立有限超时窗口，信号重复与乱序处理沿用原行为；不增加 Timer 或 Task，仍由原生快照驱动维护。Swift 对外保持原值类型接口，Rust 状态句柄采用写时复制，复制后编辑不会改变原副本。

## 维护分组去重迁移

维护不再由 Swift 对每个候选逐一扫描全体已保留分组。Rust 持有本次处理的指纹索引并决定空组拒绝、候选集合及重复拒绝，指纹相同仍按原有持久字段完整比较。Swift Hasher 保留规范等价字符串及可选数组语义，指纹字段严格对应原身份；忽略 UUID/日期/预览/收藏/捕获 hash/内联 RTF 数据。指纹不持久化，不改变归档格式。通常直接保存每个指纹的首个位置，只有不同内容碰撞才分配附加位置数组。

原生边过滤条目边送入核心，只保存接受组，保持首组原身份、日期、条目顺序；不预先复制全部过滤后的组。每 16 组和每 128 条目的取消检查、Calendar/文件有效性检查与代际提交保护未改，取消释放本次核心状态，不返回部分归档。RustGroupMaintenanceTests 独立比较 1500 组生成样例，验证规范等价、nil/空数组及忽略元数据；实际维护处理器测试验证无效图片过滤后去重、空组、逆序保留、历史/收藏筛选、源快照不变和取消。Rust 测试强制碰撞，保证指纹不是相等证明。

本机 arm64 Release，2500 个预生成合成分组（2000 个不同组加 500 个重复组），同一进程每轮先旧后新共 7 轮：旧 Swift 扫描调用原 Rust 字段比较的中位耗时 598.98 ms，Rust 索引加原生指纹/桥接/结果装配 0.468 ms，全部分组 ID 和顺序一致。原始日志 `.build/logs/group-maintenance-benchmark.log`。只测去重阶段，不含文件检查、归档写入和页面，也不代表普通少量分组、长正文或整应用 CPU/内存/能耗收益。

## 快捷规则校验与执行资格快照

Rust 对每个不可变规则快照计算校验结果及开启/未开启输入监控时的 UUID 执行资格，录制和辅助功能授权的最终门控同样由核心决定。保留旧流程先构造 UUID 集合、再按 UUID 筛选原规则的语义；即使导入记录有重复 UUID，也不擅自改为按位置判断。未修改的 Rust 校验算法继续用于缺失修饰键、重复来源及映射环路。

`RustShortcutAnalysisTests` 使用独立旧校验器对照 800 组生成规则和全部权限组合，包含重复 UUID 的原身份集合展开、空列表、未知物理位、禁用规则及并发只读/后续编辑隔离。`ShortcutAnalysisIntegrationTests` 在隔离文件及偏好域中验证实际 AppModel 的缓存复用、权限/录制切换、所有修改入口失效和未来归档拒绝；测试不请求系统权限，也不执行系统快捷键。此迁移不直接证明整应用资源下降。

## 应用动作代际、取消与截止状态

应用动作管理的开始替换、物理输入中断、应用激活拒绝及 UInt64 代际递增迁入 Rust。目标 PID 的可选性、目标已激活状态、取消、15 秒截止、源应用允许激活规则和发送目标/前台匹配均通过 Rust 值结构执行；窗口移动租约的期限与取消共用核心截止策略。没有新增 Rust 堆对象或后台线程。

## 窗口布局记忆、撤销与焦点选择

每个窗口/屏幕的最近布局、当前操作的首份撤销记录、关闭窗口清理和部分恢复决策由 Rust 拥有。保持原规则：同一操作重复记录会更新最近布局，但不覆盖该窗口的首份撤销；操作变更重建撤销批次，批次 PID 来自首条记录；部分恢复只移除已恢复撤销项，窗口关闭/句柄驱逐同时清除其全部屏幕记忆。数据仍只在本次运行内保存，无磁盘格式或用户配置变化。

Rust 保存完整几何/标志值，原生只在查询和明确获取撤销时装配展示 DTO。撤销快照由核心复制后交给原生值模型，不受后续记录、恢复、删除或历史所有者释放影响。工作队列每次轮询只查询 hasUndo，不为布尔判断生成完整撤销快照。原有串行队列仍是唯一所有者，AX 元素、NSRunningApplication 和屏幕采集继续留在 Swift。

焦点候选资格及 focused → main → 目标屏幕 → 首项的优先级由 Rust 选择，不分配候选数组；需要屏幕归属时一次构造几何列表并调用既有核心源屏幕算法，避免每个候选跨语言调用。Swift 保留 CGRect 的原生 canonical bounds 供选择，布局存储则保留原始 origin/size，包括负尺寸与符号零，不混淆两种语义。

## 配置归档结构与规则载荷

导出不再由 Swift 重复编码全部规则；Rust 复用规则记录/UTF-8 借用和逐条编码器，直接生成含 preferences、schemaVersion、shortcuts 的旧归档。偏好原生编码后作为原始 JSON 嵌入，不通过 JSON 值树重新装配；归档总是写当前版本 2，沿用旧编码器忽略 DTO 修改版本的行为。格式空白可能不同，完整 JSON 语义与字符串字节保留。正常读取由 Rust 选择归档字段、默认版本 1、优先 preferences、空值/缺失时回退 inputAutomation，并直接调用规则解码器；拥有规则与偏好 JSON，不保留输入指针。Swift 仅装配规则并解码偏好，保留原生字典/Unicode 键与旧 general 字段迁移语义。交给 Foundation 的偏好字节使用独立 Data 副本，以允许解码器自由保留输入存储，同时及时释放 Rust 规则快照。

Rust 单测验证计划不依赖已释放/修改的输入缓冲区、候选异常在删除前拒绝、空指针及失败保存输出重置。实际隔离文件测试覆盖历史/收藏/分组引用、Unicode 等价、多次合并/flush 资格、保存失败及外部损坏保护、与类型无关的字段引用、链接外部目标保留、目录递归删除、枚举及删除故障继续；平台故障注入核实归档成功写入后才枚举。性能与完整回归结果单独记录，不将所有权迁移当整应用节省证明。

本机 arm64 Release 局部基准：10000 合成记录（8000 历史/1000 收藏/1000 分组）、64 个被引用磁盘文件、每条含两类文件名，预热后 7 轮交替，每轮 5 次不变内容的完整保存与清理。参照为同一当前 Rust 保存器加冻结 4ae7040 原生清理流程，双方每次操作使用 autorelease pool，负载构造及检查不计时。重复 ASCII 名称中位 56.745417 → 21.340083 ms；不同 ASCII 名称 61.340375 → 31.392417 ms；不同 Unicode 名称 84.929250 → 86.949709 ms，本轮约慢 2.38%，不宣称所有名称场景更快。原始字节重复项提前去重，ASCII 原本已规范化直接借用，Unicode 仍用 Foundation；原生复用单个 NSMutableData 名称缓冲区，核心即时复制独立引用。结果与全部样本见 `.build/benchmarks/clipboard-cleanup.json`。未测全应用 RSS/footprint/能耗，不能把局部时间当整体资源收益。完整 Swift 回归及 60 项 Rust 单测通过。
