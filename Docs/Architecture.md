# 架构与维护

## 模块职责

```text
Aether.app（生命周期、菜单栏、设置窗口、启动准备及登录项）
├─ TimerFeature → SharedSupport + Defaults + MacroVisionKit + SkyLightWindow
├─ ClipboardFeature → SharedSupport
├─ MemoFeature → SharedSupport
├─ PromptFeature → SharedSupport
└─ ShortcutsFeature → SharedSupport + ShortcutCore
```

`App/` 是唯一装配层，负责启动、停止和协调功能模块。各模块通过公开门面暴露生命周期及 SwiftUI 页面，内部实现保持 internal。`AppRouter` 传递 `AppRoute`，由应用层决定窗口行为。功能模块不互相导入，`SharedSupport` 不访问功能实现。

`TimerFeature` 管理计时、护眼、刘海和屏幕协调；`ClipboardFeature` 管理历史、搜索、详情、粘贴及独立的常用内容；`ShortcutsFeature` 管理事件监听、应用唤醒、按键映射和快捷面板；`ShortcutCore` 提供快捷键配置与规则模型。

`PromptFeature` 管理提示词编辑状态、优化规则、兼容模型接口、本机私有凭证文件及本地历史。应用层的 `MenuBarController` 在原有 300 pt 面板提供一个可排序的 Prompt 分页，输入、结果、历史在分页内切换；设置页仍嵌入原有设置窗口。`.prompt` 路由打开菜单栏并定位该分页，`.settings(.prompt)` 定位配置页，不创建独立编辑窗口。新模块不依赖剪贴板或其他功能实现。

`MemoFeature` 管理本机待办。每项记录标题和可选截止时间；完成操作即删除该项，不保留已完成内容。`MemoStorage` 用带版本的原子本地文件保存数据，加载失败或遇到未知版本时保留原文件并停止写入。旧版数据中的废弃字段会被忽略，以保留既有待办内容。控制中心顶部的五个页面标签支持拖动排序，顺序以 `AppEnvironment` 管理的偏好域保存；缺失、重复或未知值会整理为完整的默认页面集合。

## Rust 核心边界

`Rust/AetherCore` 是 GPL-3.0-or-later 业务静态库，通过 `CAetherCore` 的版本化 C ABI 与 Swift 交互。`RustCore` 管理不可变 Rust 搜索句柄的 ARC 生命周期；计时、快捷面板状态、快捷键策略和窗口几何使用 C 值结构，复制 Swift 模型不会共享可变指针。Rust 不回调界面、不创建额外进程、不持有系统剪贴板、钥匙串、窗口或 IOKit 句柄。具体迁移进度见 [Rust 重构记录](RustMigration.md)。

搜索文档在 Rust 内拥有不可变片段的 Arc 引用；Swift 的文档类只持有独立释放的 opaque 句柄，不长期保留片段包装对象或指针跨度。合并文档克隆片段引用，原文档释放不影响派生文档。并发评分只读，销毁由 Swift ARC 保证发生在最后一个调用方释放之后；原生 Foundation 继续提供 locale 标准化与字符边界。

搜索排序向 Rust 借用分数和参考日期，输出来源索引到 Swift 提供的缓冲区；分数降序、日期降序，相同键保留输入顺序。Swift 按索引装配条目、分组和页面分类，避免完整 DTO 参与排序。非有限的瞬时 Foundation 日期无法形成全序，Rust 拒绝且不修改输出，适配层保留原生比较行为；持久归档仍拒绝非有限日期。

Swift 继续负责 SwiftUI/AppKit 页面、系统权限、事件监听、系统时钟与线程调度。搜索归一化继续使用 Foundation 和当前 locale，非 ASCII 字符边界由 Swift Character 提供，Rust 执行前缀、子串和有界模糊评分；快捷键解析、规则冲突/映射环与菜单过滤在 Rust 中计算，窗口几何通过批量借用屏幕/已占用矩形输入完成；ASCII 索引不保存逐字边界。不可变搜索句柄可并发只读，调用期间借用输入，析构只释放一次。ABI 不输出日志正文；存储/协议使用借用字节跨度和拥有缓冲区的 JSON 桥接，已有数据格式与路径保持不变。

Rust 版本固定为 1.90.0，依赖由 Cargo.lock 锁定；JSON 编解码使用固定版本 serde/serde_json，传递版本在 Cargo.lock 中锁定。`Scripts/build-rust-core.sh` 为指定 ARCHS 生成静态库，同目录临时文件完成后原子替换。Xcode 构建阶段和安装脚本都运行该步骤，Swift Package 单独测试前先执行此脚本。应用发布包不需要 rustup 或动态 Rust 库。Rust 标准库及所有锁定 crate 的许可证随应用安装；安装前自动检查声明文件与锁定源码一致。

备忘录的核心持有记录并执行版本验证、增删事务、排序与持久化；Swift `MemoStorage` 仅将平台 UUID/Date DTO 转为桥接 JSON，`MemoModel` 发布展示快照。排序由 Rust 返回索引，复用同一份原生记录。通用 `RustDisk` 提供原子文件 I/O 与 Rust 缓冲区所有权适配，Prompt 配置/历史的版本与类型校验也由 Rust 持有，原生 DTO 保留 Date/UUID 展示兼容；常用剪贴板的版本化 collections 格式及增删改/撤销事务亦由 Rust 持有，后续继续迁移历史归档及其他功能业务规则。

## 存储与启动

`AppEnvironment` 在模块启动前确定路径与偏好域，测试可注入隔离配置。

| 数据 | 位置或偏好域 |
| --- | --- |
| 应用数据根目录 | `~/Library/Application Support/Aether/` |
| 剪贴板文件 | `Aether/Clipboard/` |
| 剪贴板背景图片 | `Aether/Clipboard/Backgrounds/` |
| 常用剪贴板 | `Aether/Clipboard/quick-maps.json` |
| 快捷操作配置 | `Aether/Shortcuts/` |
| 备忘录 | `Aether/Memo/` |
| Prompt 配置与历史 | `Aether/Prompt/` |
| Prompt API Key | `Prompt/api-key.txt`，目录 0700、文件 0600；不使用钥匙串 |
| 剪贴板偏好 | `com.liyuan.aether.clipboard` |
| 快捷操作偏好 | `com.liyuan.aether.shortcuts` |
| 控制中心页面顺序 | 主应用域 `com.liyuan.aether` |
| 计时及通用偏好 | 主应用域 `com.liyuan.aether` |

`StartupController` 完成本地数据准备后才启动功能模块，避免历史清理或事件监听与数据写入竞争。现有数据兼容处理集中在启动层及 `SharedSupport`，功能模块不承担外部数据识别。修改兼容处理前应检查已有数据与失败恢复路径。

`DataMigration` 使用复制、校验及同卷暂存目录移动；`copied` 阶段支持重试偏好导入，`complete` 阶段不再覆盖数据。无法识别的已有目标目录会停止处理，不得静默清空。后续格式升级同样需要明确版本、幂等行为及恢复策略。

Swift Package 测试进程默认使用临时根目录和随机偏好域。测试数据必须合成或脱敏，真实剪贴板内容不得进入日志、测试输出、截图或 Git。

### 剪贴板背景

背景视图只绘制在完整剪贴板窗口内容下方，不接收鼠标事件；毛玻璃保持为底层。透明度、缩放及九宫格位置复用缓存，静态图片复制和解码使用模块内的图片队列。窗口适配保留以太原有默认尺寸，图片比例模式最小宽度为 1120 pt（小屏受 94% 可用区域上限约束），保证列表、详情及常用内容可用；调整时保持中心并限制在当前窗口所在屏幕。

启动层在初次迁移之后执行版本化的背景补充迁移，由 `ClipboardModule` 提供校验和复制接口。已有 Aether 任一背景设置时不覆盖；图片验证并原子保存成功后才导入偏好，最后记录迁移版本。失败不会写入成功标记，保留旧图片及偏好供重试，原数据不会删除。背景设置使用 `AppEnvironment.clipboardDefaults`，图片与历史、常用内容独立。

### 常用内容

完整剪贴板窗口在顶部右侧提供常用内容按钮；点击后以约 320 pt 的原生弹出面板打开，不挤压历史列表和详情，也不依赖窗口宽度或额外的展开偏好。该区域只属于完整窗口，不新增控制中心分页或应用路由。

`QuickClipboardStorage` 将多个自动命名的常用项及其中按创建顺序排列的标题和纯文本内容保存到独立的版本化文件。新建名称依次为「常用 1」「常用 2」等，并跳过已有名称。写入使用同目录临时文件和原子替换，未知版本或损坏文件会阻止覆盖。该文件不参与剪贴板历史维护、过期清理和分类清空；内容仅通过用户明确操作删除。内容为本机明文，但错误、复制反馈和测试输出不得包含正文。

常用条目复制复用 `ClipboardStore` 的纯文本写入协调，在写入系统剪贴板后同步监控基线，因此不会把 Aether 自己的复制再次记录为历史。右栏键盘事件按当前交互区域分发；文本输入控件优先处理编辑命令，避免与历史列表的 Enter 和 Esc 行为冲突。

### Prompt 请求与持久化

Rust 核心执行 Prompt 请求体/响应协议、接口路径策略、请求代际和历史索引计划；原生 URLSession/URLComponents、Task、locale 匹配保留平台语义。Prompt 配置和历史文件由 Rust 校验并持有独立写入保护状态，各有版本封装，原子写入并限制本地访问权限。加载失败或遇到未知版本时保留原文件并阻止覆盖，以便恢复后重试。API Key 使用独立可注入的本机私有文件存储，不进入配置/历史 JSON、请求错误说明或日志；通用 Rust 文件层执行私有权限、符号链接拒绝和同步原子写入。Prompt 不调用 Security/钥匙串，不触发系统密码验证。旧钥匙串记录保留，不自动读取或删除；升级后需重新填写并保存一次 Key。配置只保存 Key 的摘要用于一致性校验；配置写入失败会回滚 Key，即使回滚失败并重启，下次请求也会先检查摘要，避免旧服务地址误用新 Key。测试使用临时目录、模拟凭证存储和隔离 URLSession。

客户端使用非流式 Chat Completions 请求，只发送系统优化规则和本次用户输入；不附带历史，也不自动读取剪贴板。远程地址要求 HTTPS，允许本机回环 HTTP；拒绝地址中混入凭证、查询参数或片段。网络重定向不会继续携带凭证，请求设置超时，错误反馈不显示服务端原始响应正文。

编辑状态位于主线程模型中，每次请求固定输入及配置快照，并使用独立请求标识。取消、新建和选择历史使旧标识失效，即使网络晚返回也不能覆盖当前结果。收起菜单栏或切换功能分页不取消请求，模型保留输入、进度与结果；再次打开可继续使用。只有成功且完整的结果才进入历史；历史写入失败时仍保留编辑区结果并显示错误。保存开关控制后续记录，既有记录由明确删除操作管理。

## 窗口与输入协调

唯一菜单栏控制器负责紧凑面板，完整剪贴板窗口负责搜索、详情、常用文本复制和粘贴协调。打开应用界面前保存外部应用作为操作目标，切换分页时不重新捕获目标。

应用层协调用户快捷键规则与剪贴板 Carbon 内置组合；冲突时不注册内置组合，保证自定义动作优先。打开 Aether 功能的动作应交给内部路由，避免启动额外应用进程。

应用窗口操作由 `ApplicationIntent`、`ActionExecutor`、`ApplicationWindowMover` 和 `WindowMoveWorker` 协调。事件线程在真实按键、点击和滚动时同步使旧操作失效；工作区激活通知补充检查焦点变更。后台启动回调、延迟命令、窗口写入及窗口选择均检查同一个操作凭据。新建窗口命令同时检查前台进程并向指定 PID 发送，不能以固定延迟假定焦点已正确切换。

窗口 AX 访问、布局记忆和 `WindowMoveSession` 状态全部限定在 worker 的串行队列；主线程只接收可发送的快照与结果。已运行应用使用首次清单，启动或新建窗口使用最多 1.5 秒的等待和固定 120 毫秒收集期。独立超时先关闭窗口写入凭据再继续激活，完成后不再观察或移动后来出现的窗口。公开 AX 调用无法撤回应用已接受的异步操作，不应宣称能消除所有应用动画。

`WindowLayoutHistory` 按本进程分配的窗口 ID 和显示器记录布局与一次恢复批次，仅驻留内存；AX 句柄消失时清理对应记录，并限制其他应用的历史句柄缓存。记录不保存窗口标题、文档路径或正文。`ApplicationShortcutPreferences` 新增可选的最小化恢复与应用例外字段，缺失时采用原有默认行为，不需要启动时重写已有配置。

计时布局与屏幕协调由 `TimerRuntime` 管理。模块内的控制窗口辅助代码受 `timerControlWindowEnabled = false` 禁用；更改窗口入口时需要同时检查 Live Activity 行为。菜单栏面板问题应在对应控制器中解决。

## 设置

应用层持有唯一侧栏，页面标题共用 `SharedSupport.SettingsContent`。剪贴板使用原生 Form 设置行；快捷操作通过顶部分段选择器切换按键与面板、应用唤醒和快捷键。规则在同一列表中展开编辑，同时仅展开一条，不嵌入另一套设置侧栏或独立对话框。配置导入导出位于快捷操作配置区，启动数据准备失败通过通用页重试。

## 计时准确性

手动倒计时通过 `ContinuousClock` 和 `ManualCountdown` 的截止时间计算剩余时长。1 Hz 回调只刷新显示，不逐次累减；暂停保存精确剩余值，恢复重新建立截止时间。唤醒立即重新采样，UI 回调延迟与系统休眠不会丢失时间。零值、负数、非有限时长不会中断现有计时。应用退出后手动计时结束，重开为空闲；系统镜像按当前系统状态重新发现。

## 变更与验证

依赖版本在包清单与 `Package.resolved` 中固定，应用构建与模块测试使用仓库内配置。调整依赖、公共接口或数据格式时，同步检查调用方与兼容路径。

测试覆盖快捷键规则、剪贴板搜索与数据处理、常用内容持久化与检索、粘贴计划、护眼状态机、数据恢复、导航与连续时间倒计时。自动粘贴、权限及屏幕布局必须在正式安装副本中验收，详见[验收清单](Verification.md)。

## 端口模块

`PortsFeature → SharedSupport + WhatPortCore + WhatPortIOKit`。两个 WhatPort target 的固定源码在仓库内，来源版本及 MIT 声明见 NOTICE；不依赖外部源码目录。`PortsModule` 暴露摘要、详情和可见性接口，应用层通过现有 `.settings(.ports)` 路由打开唯一设置窗口。

`PortsModel` 在主线程协调两个界面的共享会话。全都不可见、窗口最小化、应用隐藏或系统休眠时取消订阅；恢复时创建新数据源，旧会话标识拒绝迟到回调。`LivePortDataSource` 使用单一 utility 串行队列执行 IOKit/SMC 读取、1秒计时器和停止释放，通知只把刷新排入该队列；快照流只缓冲最新一项。无页面可见时不初始化硬件读取器。功率曲线另用带时间戳和分段的内存窗口，最多保留60秒，缺失读数及采集会话边界不连线。不会持久化端口数据或设备序列号。

上游未公开的 IOKit 属性、SMC key 和生命周期消息仅作为当前可读取的数据源，不保证跨机型或 macOS 版本稳定。保留上游端口关联和降级逻辑；展示层不猜测缺失读数，不将累计错误转换成硬件诊断。

常用剪贴板通过借用命令字节跨度调用 Rust；Rust 持有记录及归一化比较索引，分组名称/精确标题比较的归一化来自 Foundation。正文和未修改的条目数组使用 Arc 共享，写入成功后只返回受影响分组的原生展示补丁。查询只将匹配类型、时间和分组范围交给 Rust 排名，不将正文放入日志或额外检索副本。

剪贴板历史策略通过 UUID/时间/类型/比较标志的借用数组调用 Rust，返回复用原生记录的索引计划；插入、保护裁剪、有效/过期筛选及收藏转移在核心执行。核心选择内容比较字段，原生 String/Data 比较与 RTF 文件读取维持平台行为。`abi.rs` 保存跨功能基础类型，Rust 功能模块不经其他功能模块取得通用字节或 UUID 类型。归档所有权、调度状态与完整持久化迁移仍在进行。

剪贴板调度使用 Rust 值状态机保存捕获重试、历史修订、维护代际及写入合并/清理状态。原生 Task/DispatchQueue 负责执行，归档 DTO 快照暂由 Swift 保存；系统时间和 changeCount 在调用时借用输入。资源清理由 Rust 对 canonical composition 的文件名集合规划，只在原子归档写入成功后通过原生文件接口执行。写入器的目录可注入，测试不触及真实历史或负载。

剪贴板归档的 Rust 句柄保存路径和覆盖阻止状态，按旧的无版本 history/pinnedItems/groups 格式校验，再移交读取缓冲区给原生 Codable DTO。缺省 UUID/Date/预览仍由原生生成；Rust 校验借用未转义字符串，不保留另一份正文。重复 JSON 字段沿用原生首次出现值，额外 Base64 padding 和未知字段的嵌套深度维持 Foundation 接受边界。读取失败或发现外部损坏后阻止覆盖和负载清理，明确重载有效文件才能恢复。完整记录所有权与展示 DTO 编解码仍需迁移。

端口连接生命周期的 episodes 由 Rust 持有，原生 IOAccessoryManager 信号转为固定 C 枚举，原生快照时钟驱动超时和回拨重置。Swift 的公开值类型适配器采用写时复制，复制后第一次修改才克隆 Rust 状态，保持原 struct 的独立行为；查询只生成端口 ID/阶段展示映射。IOKit 句柄、监听队列、端口关联和电源采样尚在原生层，相关业务仍需继续迁移。

端口图表的 60 秒时间窗、100 ms 突发限制、2.5 秒连续性和方向/会话分段由 Rust 历史核心执行。核心持有数值点及时间/方向/分段状态，Swift 保留 UUID 图表投影；每次调用只移交新增/删除事件，批量删除过期 token，未变化的原生点 ID 不重建。状态写时复制保持 PortHistory 值语义；无效/缺失读数不创建额外端口状态，全部点过期后释放该数组容量。

USB 设备拓扑由 Rust 批量构造：一次建立首个位置 ID 索引和子节点表，返回深度优先顺序、层级和直接父节点索引。位置路径最多六级，空洞或越界位置仍作为无父节点；重复位置 ID 的原始数组项各保留一次，子树只在第一次访问该位置时展开。Swift 继续复用原生 DeviceInput 的字符串和展示格式，不向 Rust 复制设备名称；无父节点索引在原生使用前检查上下界。公开 DeviceTree 查询接口也通过同一核心执行。

SMC 充电归属由 Rust 执行全部选择规则和数值校验：4500 mV 最低电压、正功率/电流、2% 内部一致性、usb host 输出标签和大于 0.5 W 的输出排除。已有任意输入电源或系统 winning contract 阻止估算，USB-C 裸节点阻止对应端口归属，必须恰好一个符合条件的通道。resolve 采用第一个 UUID 匹配，连接证据查询则接受任意符合条件的匹配，二者不合并。Swift 只桥接原生 DTO、UserDefaults 开关与原生 String 规范等价/小写比较；身份 token 保留第一次同 key 的输出读数。未启用或无外部电源先经核心快速判断，不构造桥接数组；IOKit 读取行为不变。

端口代表选择与显示数据级别确认由 Rust 执行。雷雳同 socket 选择最大链路宽度，同宽度保留首个记录；PHY 在至少一个已知端口号时按端口/回退 PHY ID 合并、活动通道替换空闲通道并按键排序，完全没有映射时原数组不去重不排序。原生只借用 ID/宽度/活动标志，按返回索引复用 DTO。数据级别状态是 C 值结构，较差级别需连续两次相同读数才确认；同级或更好立即确认并清空等待值，不延迟端口本身的读数。

端口电源应用由 Rust 返回电源补丁。USB-C 充电节点先筛选正端口号/正合同功率，再按首个节点关联，仅填入已连接且无电源的端口；SMC 合同按已解析的端口 ID 更新首个匹配，仍标记为估算合同。SMC 输出按规范等价 UUID 身份 token 关联首个通道，仅正功率覆盖非输入电源，同时保留已有 PD/VConn/估算标记。Rust 执行毫单位转换和四舍五入，Swift 保留原有 checked Double-to-Int 转换与整数 DTO，不提前转换未选中的输出通道；私有标量接口不传递设备名称。

USB-C 名册规划由 Rust 一次执行 HPM/雷雳/PHY 来源选择、稳定顺序、直接或位置 PHY 映射，以及首个电源/USB-C CC 关联。HPM 非 MagSafe 记录保留全部原数组项并稳定按端口排序；无 HPM 时使用雷雳代表的已排序 socket，再回退 PHY。Rust 返回原始数组索引、端口 ID、CC 标志和 tier，Swift 只构造原生 PortState/健康展示 DTO。规划同时返回雷雳代表索引，后续链路关联复用这一选择，不再次计算。

端口身份消除修复及 PD 计数序号关联/跨来源交叉校验由 Rust 规划；原生字符串字典生成身份 token，保持 Unicode 规范等价和 UUID 规范化行为，并区分 nil UUID 与实际空字符串。重复 PD offset 保留首项，重复端口 ID 保留最后有效关联；重复通道或重复 UUID 保持未解决，任何明确冲突清空整批计数归属。身份修复必须满足唯一缺失项、唯一空闲通道、来源总数一致与稳定端口位置一致，仅返回原数组索引。

传输关联由 Rust 对整批端口执行，USB 取首个活动或受限节点，DP/CIO 实时链路取首个活动节点，HPM 运输列表取首个非 MagSafe 记录，CIO 隧道列表和设备身份取首个原始节点。仅首个 CIO 活动且该端口已有雷雳链路时发布其设备身份，不回退到后续活动记录。核心一次建立索引并返回每个端口的原数组索引，替代逐端口三次线性搜索；原生桥接只传标量，保留 USB/DP/雷雳显示顺序及全部原生文字字段。

非 USB-C 连接器的供电规则复用 Rust 电源核心：按物理端口取首个非 USB-C 的有效获选合同；USB-C 节点合同优先于全部连接器，而有效的本连接器合同或 SMC 归属可覆盖较弱的 USB-C SMC 证据。只在连接器活动且系统输入遥测为正时发布功率，充电/满电/健康暂停状态不参与此门控。合同字段来自获选合同，测量字段来自系统输入，缺失合同保持零并隐藏该行。Swift 只保留原生字符串分类、100 加端口号的身份映射及展示 DTO。来源索引一次建立，重复项和原数组顺序不变。

端口基础状态由 Rust 解码通道精确类型/电源状态、当前雷雳 generation/宽度/每通道速率、正输出功率及累计能量有效性。Swift 保留 Unicode 小写转换，UTF-8 缓冲仅在同步调用中借用，不分配 Rust 字符串；客户端、DP 原始文字和 IOKit DTO 保留原生。未知/组合宽度回退 1 TX/1 RX，未知正 speed 回退 TB4；非正链路不发布。累计能量独立于即时功率，为正样本数及非负累计值时仍可显示。

应用排序和拖动偏好更新由 Rust 规划，原生字符串字典生成 bundle identifier 身份 token，保持 Swift Unicode 规范等价。展示排序保留偏好中的重复项及首个应用记录，末尾只追加未出现应用；保存拖动顺序时规范化偏好，暂未安装项保留原位置。返回来源/索引，Swift 从原字符串投影，不改变原始 UTF-8 表示。ABC 自动切换防护的五秒手动授权、手动会话、失效/恢复判断由 Rust 状态转移；物理按键监听与输入法动作继续原生执行，禁用/无法观察时的状态保留行为不变。

端口原生采样层每轮只枚举一次 AppleSmartBattery，共用一次完整属性读取生成输入电源与适配器身份。PowerOutDetails 保持独立属性读取，完整属性调用失败不抑制有效输出功率或计量可用性。跨服务输出按顺序追加、可用性取任一存在、输入/身份保留最后成功解析的原规则；不跨轮缓存真实遥测。采样函数使用局部 autoreleasepool 释放临时桥接对象，返回的强引用原生 DTO 保持有效，1 秒轮询和生命周期事件频率不变。

快捷操作偏好的默认值、版本、旧 general 字段覆盖、存储来源和迁移写入门控由 Rust 决定。Rust 负责普通配置的协议字段/类型读取，原生字符串等价回调保留字典语义；app 键存在（包括 null）阻止继承旧登录项，旧 ABC 值仍可覆盖。文件系统存在性/IO/错误保持原生平台适配，当前文件优先，只有明确要求且旧来源或旧版本时保存，未来标签沿用既有接受且不自动覆盖的行为。窗口行为、长按范围、物理输入法按键和字母键映射也由 Rust 处理；字母桥接保留原生大小写和 Unicode 规范等价，原生中文文案/拼音分组保留。

剪贴板文档最高评分聚合由 Rust 单次借用片段句柄执行，不可变文档缓存句柄数组并强持有各片段，调用期间不重复建立数组。原生 ARC 所有者在调用结束前保持有效。空文档返回无匹配，单片段沿用评分快速路径；原生归一化、稳定排序和每批取消检查保持不变。

剪贴板归档加载使用 Rust 拥有的不可变记录集合，字段校验、重复键优先级和缺省字段存在标记在核心生成。C 视图的文本跨度只在集合存活期间有效，Swift 在释放集合前复制全部文本/URL/二进制与群组值；原生 UUID、时钟、URL/Character 预览和 Base64 数据转换保留既有语义。加载不再重复执行 Swift JSONDecoder，保存使用批量字段/UTF-8 数据桥接，由 Rust 校验后序列化为兼容 JSON 并原子替换，生产路径不再调用原生 JSONEncoder。读取错误或原生值转换失败继续阻止保存，直到显式成功重载；外部文件修改校验不省略。

归档保存桥接以一个连续 UTF-8 缓冲区与字段/URL/分组跨度交付数据。Rust 在调用内借用字节，检查分区、分组连续范围与 URL 范围，拒绝非法类型、UUID、日期或数据，序列化完成后不保存原生指针。nil 字段省略、空字符串/URL 数组保留，groups 的缺失与空数组保持区别。外部文件校验和损坏后的显式重载要求不变。

端口增强关联由 Rust 批量建立设备分组及显示器、统计、CC 线缆和 MagSafe HPM 来源索引。保留设备枚举顺序、重复端口、来源首项优先；线缆先选择首个 USB-C CC 记录再检查内容，空首项不回退到后续记录。MagSafe 只通过物理编号匹配 MagSafe HPM，不吸收 USB-C 健康记录。原生 DTO 字符串和所有遥测字段按返回索引装配，借用计划在复制索引后销毁。

USB 设备类别、首个非 hub（否则首个 hub）及附加非 hub 数量由 Rust 执行。PortState 的设备数组每次修改更新值缓存，页面读取不重复扫描/过滤。数组元素原地修改、追加/删除、反转和结构体复制保持原生值语义，不持有 Rust 可变句柄；不改变页面或采样频率。

通用、登录项、计时器及 SMC 开关的偏好访问统一经过 AppEnvironment.appDefaults。普通运行仍为 UserDefaults.standard，保留原键名和注册默认值；测试为每个进程独立的应用域。计时器 44 个 Defaults.Key 及 AppStorage 显式绑定该域，避免静态键或协调器绕过测试隔离。WhatPortCore 通过 SharedSupport 消费环境域，不引入功能模块依赖或反向访问。

资源性能配置在任何功能初始化前由 AppEnvironment 解析；只接受 .build/resource-profiles/UUID/profile.json 的版本化清单及真实目录，非法请求中止而不选择用户存储，数据树符号链接被拒绝。各偏好域独立重置为固定负载值，粘贴板使用独立名字；普通启动仍使用现有目录、标准域及系统粘贴板，单元测试使用自己的域与粘贴板。

隔离性能运行跳过旧应用迁移、登录项变更和快捷键动作服务，外部粘贴及系统计时器监控停用；剪贴板仍按原频率轮询私有板，端口继续采样真实硬件。原生页面结构保持原样，配置只用于受限固定场景比较，不用于完整权限/交互验收。就绪后记录隔离运行 PID/清单 ID，开发启动参数可选择关闭设置、通用、端口或合成剪贴板窗口。

剪贴板搜索快照只持有一份 rankedItems；RustClipboardSearchBuckets 拥有不可变的分类位置表，不借用 Swift 输入。分类遵循既有收藏成员集合和类型规则、保持排名顺序；覆盖全部来源时返回 identity 标记，Swift 利用 Array 写时复制共享原数组，其余分类只在呈现时装配。面板 State 保留 UUID 到位置的索引，条目和分组查询使用当前数组，不另存 UUID 到完整 DTO 的字典。Rust 句柄的借用跨度只在同步调用且 owner 存活期间读取，允许并发只读。

ClipboardSearchVocabulary 在同一搜索索引内复用各条目类型的规范化 RustSearchSegment，最多六个。每条 Rust 文档通过 Arc 共享这些不可变类型片段，正文和路径保持各自索引及原有顺序；同步条目/分组查询也在一次调用内复用。缓存不按正文建键，不增加任意用户内容的保留期。原生类型名称和 Foundation 归一化仍由 Swift 提供，类型片段包装释放后文档保持独立 Rust 所有权。

剪贴板分组交互状态由 clipboard_groups Rust 模块返回索引计划。创建先复用既有 UUID 去重规则，核心拒绝不足两项，按来源顺序请求原生持久字段比较并选择首个匹配分组；匹配组保持原 UUID/日期/条目，只有确需新建时 Swift 生成 UUID 和 Date。激活在 NSPasteboard 写入成功后才请求置顶，未找到组仍保持原有保存行为；删除移除所有相同 UUID，清空返回空计划。字段比较回调仅在同步借用的上下文存活期间调用、不保留指针、不抛异常。Rust 不分配排序数组，直接写调用方缓冲区；identity 标记允许原生数组共享，仍保留既有发布/保存时机。

维护分组去重使用每次处理独立的 Rust accumulator，拥有指纹到已保留位置的表。Swift 在单个候选组完成平台有效性检查及 Rust 条目筛选后送入；空组由核心拒绝，指纹相同的候选按原保留顺序回调比较完整持久字段。指纹通过 Swift Hasher 合并条目顺序、类型、可选正文、图片文件名、可选文件 URL 数组及 RTF 文件名，保留规范等价 String 语义；UUID、日期、预览、收藏标志、图片捕获 hash 和内联 RTF 字节不属于原分组身份，因此不纳入指纹。指纹不是相等证明、不持久化；碰撞仍比较完整字段。通常每个指纹直接保存首个位置，只有不同组发生碰撞才分配附加位置数组。

原生只保存已接受的展示组，不建立全体过滤后分组的第二份快照；同步回调使用栈上下文且不保留指针。累积状态在处理结束或取消后释放，文件检查、每 16 组/128 条目的取消检查及源代际提交保护保持原时机。文件 I/O、Calendar 和 Task 继续是平台适配，完整记录业务所有权和归档资源事务仍需继续核对迁移。

默认快捷规则的静态目录和升级版本图位于 Rust；Swift 只将静态描述和有序索引计划装配为原生规则，保留 Foundation 路径语义、UUID 与字段相等比较。比较回调不逃逸，不保留用户规则。每调用按需装配规则，不使用全局原生默认规则缓存；无变化计划复用原数组。

快捷操作模型持有当前规则的不可变校验/执行分析；Rust 计算身份集合和权限资格，Swift 缓存校验输出及原生快照。规则数组发生任何写入即失效，权限和录制门控按当前状态执行。分析不保留借用指针或 Rust 校验句柄，可跨线程只读；主线程模型负责缓存生命周期、通知和持久化。

应用动作和窗口移动租约使用 Rust 值状态维护代际、取消、激活归属与截止。Swift NSLock 保护每次读取和更新，保留原有管理器到令牌、租约到父动作的锁顺序；UUID、时钟、强引用和 macOS 动作接口仍由原生层负责。状态不使用跨语言裸对象指针，无额外后台线程或 Rust 堆生命周期。

窗口布局记忆和当前撤销批次由 Rust 保存完整值数据；原生仅按需装配 SavedWindowLayout/WindowLayoutUndo。工作器轮询使用 hasUndo 轻量查询，明确撤销才生成独立快照。沿用窗口工作器串行队列，不在核心保存 AX/应用对象或窗口标题。焦点候选与优先级在 Rust 内选择，CGRect 原始存储和 canonical 几何选择分别适配。

窗口移动进度为 Rust C ABI 值状态，包含目标几何、下一次尝试、计数和标志；原生保留平台快照与调用。核心返回移动/恢复/不操作指令，原生执行后提交确认，再由核心决定历史记录资格。完成汇总只接收紧凑几何和状态，返回焦点/撤销来源位置；所有借用缓冲区均不逃逸。启动收集间隔和 scope 时限也由核心维护。


窗口初始冻结通过 Rust 索引计划执行三种范围筛选与布局判断。原生传入 canonical 几何及同屏所需的原始 CGRect 值；同步查询回调仅在借用上下文存活期间读取布局记忆/撤销，不持有平台句柄。核心共享焦点策略，先计算源屏幕与占用位置，再按原顺序生成目标位置；输出直接装配原生 Progress，计划析构不影响已装配状态。


应用分组与默认值由 Rust ApplicationCatalog 索引计划计算；原生 String 负责规范等价 token 与标题排序，核心共享已有应用排序器并执行默认/种子优先级。模型缓存装配后的不可变 Swift 目录，应用注册、任何规则写入和默认/排序偏好更新立即失效；其他通用偏好不引起重新分组。种子写入仍经过原有偏好更新和持久化通知，不覆盖已有配置，旧目录快照不受后续变更影响。


ShortcutRuleIndex 由 Rust 拥有不可变 UUID/触发键/启用元数据及首位置表；模型按规则代际缓存，任何规则数组写入即失效，不保留第二份完整规则。更新/删除返回索引、选择与扫描资格，移动返回原数组位置计划；原生负责装配和原有引擎/保存/冲突通知顺序。有效重排一次发布最终数组，避免为每个删除步骤建立临时可观察数组。


快捷规则保存 JSON 由 Rust 逐条编码，保留既有顶层数组、关联动作、可选字段、UUID 与修饰键表示。Swift 只将原生 DTO 转成紧凑记录和共用 UTF-8 缓冲区；核心同步借用并检查字符串跨度，不保留原生地址，也不建立第二份完整规则列表。返回缓冲区直接交给 Data 持有，沿用原子文件写入。读取由 Rust 逐条解码并拥有紧凑记录/字符串缓冲区，Swift 在一次同步借用内装配原生值并释放核心快照。对象类型、动作选择、UUID、逻辑位裁剪及缺省物理位由核心处理；重复键沿用首值语义，整数小数/指数表示使用精确十进制运算。普通文件不再执行原生 JSONDecoder；核心拒绝的特殊编码/失败输入才交给旧解析器，以保留 Foundation 历史文本编码与错误类别/路径/文案。配置归档复用同一规则编解码器；页面保持现有实现，保存协调使用 Rust 配置存储。


配置导入/导出使用 ShortcutConfigurationJSON，Rust 直接在归档中序列化紧凑规则，不生成中间规则 JSON；读取拥有规则快照和原偏好 JSON 字节。偏好由 Rust 解码，原生字符串等价回调保留规范等价字典键语义；特殊编码与失败输入保留 Foundation 兼容解析。核心处理归档版本默认值、preferences/inputAutomation 选择及已归一化版本的接受门控；核心或偏好解码失败才回退完整旧归档解析，保留错误路径及历史文本编码。原生负责用户所选文件的原子导出、DTO 装配、模型发布与通知；Rust 协调规则/偏好的整组保存、失败回滚及恢复。


偏好保存编码使用 Rust PreferenceJSON 桥接。Swift 从现有字典装配紧凑条目、列表跨度及共用 UTF-8 输入，保留已由 Swift 确定的规范等价键成员；Rust 只对借用键排序并序列化，不复制字符串为另一棵 JSON 值树。配置、通用及应用快捷字段与版本由核心输出，有限浮点保持原值，不在存储时裁剪。非有限值沿用原生编码器报错，归档导出继续保留完整归档错误路径。普通读取由 Rust 解码，归档导出复用同一保存编码器；原子写入、加载迁移时机与模型通知保持原流程。


偏好读取复用既有 Rust 默认值与 general 迁移策略，核心拥有完整标量、字典条目、列表及 UTF-8 缓冲区。同步回调只将每个字典键转换为原生 String 等价 token；三个字典分别保留首个键的字节与身份。Rust 按 token 保留首值并跳过后续值的语义解码，Swift 装配时复用已建立的原生键，不持有核心地址。常规配置同时返回存储版本，消除原生版本头与配置的重复扫描；非标准数值版本仅回退原生版本头读取。特殊文本编码和解码失败回退旧配置解析，保留精确错误；归档仅需配置值时跳过版本头兼容扫描。所有回调均同步、上下文每调用独立，不存储原生对象指针或新增线程。


ShortcutConfigurationPersistence 拥有 Rust 配置存储句柄；后台任务强持有包装器，最后一个调用返回后才销毁核心。Swift 在触碰目标文件前完成两份 DTO 编码；Rust 仅在同步调用内借用两份输出缓冲区，不复制或保留输入指针。Rust 持进程内磁盘锁执行版本化私有日志、文件/目录同步、两份替换与提交标记。未提交恢复记录还原原始字节、权限及符号链接；已提交记录只清理。恢复前验证两份目标仍为本次原/新内容，外部不同内容、未知/损坏日志阻止恢复及后续保存，不覆盖用户数据。AppModel 启动先恢复再读取；导入与 flushSave 只在整组提交后发布/继续，成功导入保持首项选择及引擎、偏好、冲突扫描通知顺序。

日常规则/偏好保存使用分别递增的原子 ticket，在排队时取得；较新同类编辑使旧任务失效，整组提交使两个槽的旧任务失效。预检查可跳过已过期快照编码，持磁盘锁后再次校验以覆盖竞态。ticket 预留/查询不等待磁盘 I/O，普通保存继续采用原有 0.25 秒延迟；两个槽互不取消。无改动整组保存比较原始文件字节后不写日志/目标，仅使旧任务失效，避免重复退出写入。独立 ShortcutRuleStore/AppPreferencesStore 继续提供原有文件接口；生产 AppModel 的保存通过同一协调器，启动迁移仅在恢复成功后执行。

双路径采用可恢复事务，不能把两次 rename 称为同时原子切换；外部读取者可能在两个替换之间观察中间态。应用只在提交后发布，进程中断后按持久标记恢复。正式应用限定一个主进程；此锁不提供跨进程写入协调，不宣称突然断电/硬件故障的实测保障。整组更新增加必要日志与同步 I/O，未将本阶段等同于整体资源下降。
