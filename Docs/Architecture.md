# 架构与维护

## 模块职责

```text
Aether.app（生命周期、菜单栏、设置窗口、启动准备及登录项）
├─ TimerFeature → SharedSupport + Defaults + MacroVisionKit + SkyLightWindow
├─ ClipboardFeature → SharedSupport
├─ MemoFeature → SharedSupport
├─ PromptFeature → SharedSupport
└─ ShortcutsFeature → SharedSupport + ShortcutCore
```

`App/` 是唯一装配层，负责启动、停止和协调功能模块。各模块通过公开门面暴露生命周期及 SwiftUI 页面，内部实现保持 internal。`AppRouter` 传递 `AppRoute`，由应用层决定窗口行为。功能模块不互相导入，`SharedSupport` 不访问功能实现。

`TimerFeature` 管理计时、护眼、刘海和屏幕协调；`ClipboardFeature` 管理历史、搜索、详情、粘贴及独立的常用内容；`ShortcutsFeature` 管理事件监听、应用唤醒、按键映射和快捷面板；`ShortcutCore` 提供快捷键配置与规则模型。

`PromptFeature` 管理提示词编辑状态、优化规则、兼容模型接口、钥匙串凭证及本地历史。应用层的 `MenuBarController` 在原有 300 pt 面板提供一个可排序的 Prompt 分页，输入、结果、历史在分页内切换；设置页仍嵌入原有设置窗口。`.prompt` 路由打开菜单栏并定位该分页，`.settings(.prompt)` 定位配置页，不创建独立编辑窗口。新模块不依赖剪贴板或其他功能实现。

`MemoFeature` 管理本机待办。每项记录标题和可选截止时间；完成操作即删除该项，不保留已完成内容。`MemoStorage` 用带版本的原子本地文件保存数据，加载失败或遇到未知版本时保留原文件并停止写入。旧版数据中的废弃字段会被忽略，以保留既有待办内容。控制中心顶部的五个页面标签支持拖动排序，顺序以 `AppEnvironment` 管理的偏好域保存；缺失、重复或未知值会整理为完整的默认页面集合。

## Rust 核心边界

`Rust/AetherCore` 是 GPL-3.0-or-later 业务静态库，通过 `CAetherCore` 的版本化 C ABI 与 Swift 交互。`RustCore` 管理不可变 Rust 搜索句柄的 ARC 生命周期；计时、快捷面板状态、快捷键策略和窗口几何使用 C 值结构，复制 Swift 模型不会共享可变指针。Rust 不回调界面、不创建额外进程、不持有系统剪贴板、钥匙串、窗口或 IOKit 句柄。具体迁移进度见 [Rust 重构记录](RustMigration.md)。

Swift 继续负责 SwiftUI/AppKit 页面、系统权限、事件监听、系统时钟与线程调度。搜索归一化继续使用 Foundation 和当前 locale，非 ASCII 字符边界由 Swift Character 提供，Rust 执行前缀、子串和有界模糊评分；快捷键解析、规则冲突/映射环与菜单过滤在 Rust 中计算，窗口几何通过批量借用屏幕/已占用矩形输入完成；ASCII 索引不保存逐字边界。不可变搜索句柄可并发只读，调用期间借用输入，析构只释放一次。ABI 不输出日志正文；存储/协议使用借用字节跨度和拥有缓冲区的 JSON 桥接，已有数据格式与路径保持不变。

Rust 版本固定为 1.90.0，依赖由 Cargo.lock 锁定；JSON 编解码使用固定版本 serde/serde_json，传递版本在 Cargo.lock 中锁定。`Scripts/build-rust-core.sh` 为指定 ARCHS 生成静态库，同目录临时文件完成后原子替换。Xcode 构建阶段和安装脚本都运行该步骤，Swift Package 单独测试前先执行此脚本。应用发布包不需要 rustup 或动态 Rust 库。Rust 标准库及所有锁定 crate 的许可证随应用安装；安装前自动检查声明文件与锁定源码一致。

备忘录的核心持有记录并执行版本验证、增删事务、排序与持久化；Swift `MemoStorage` 仅将平台 UUID/Date DTO 转为桥接 JSON，`MemoModel` 发布展示快照。排序由 Rust 返回索引，复用同一份原生记录。通用 `RustDisk` 提供原子文件 I/O 与 Rust 缓冲区所有权适配，Prompt 配置/历史的版本与类型校验也由 Rust 持有，原生 DTO 保留 Date/UUID 展示兼容；常用剪贴板的版本化 collections 格式及增删改/撤销事务亦由 Rust 持有，后续继续迁移历史归档及其他功能业务规则。

## 存储与启动

`AppEnvironment` 在模块启动前确定路径与偏好域，测试可注入隔离配置。

| 数据 | 位置或偏好域 |
| --- | --- |
| 应用数据根目录 | `~/Library/Application Support/Aether/` |
| 剪贴板文件 | `Aether/Clipboard/` |
| 剪贴板背景图片 | `Aether/Clipboard/Backgrounds/` |
| 常用剪贴板 | `Aether/Clipboard/quick-maps.json` |
| 快捷操作配置 | `Aether/Shortcuts/` |
| 备忘录 | `Aether/Memo/` |
| Prompt 配置与历史 | `Aether/Prompt/` |
| Prompt API Key | macOS 钥匙串，服务 `com.liyuan.aether.prompt` |
| 剪贴板偏好 | `com.liyuan.aether.clipboard` |
| 快捷操作偏好 | `com.liyuan.aether.shortcuts` |
| 控制中心页面顺序 | 主应用域 `com.liyuan.aether` |
| 计时及通用偏好 | 主应用域 `com.liyuan.aether` |

`StartupController` 完成本地数据准备后才启动功能模块，避免历史清理或事件监听与数据写入竞争。现有数据兼容处理集中在启动层及 `SharedSupport`，功能模块不承担外部数据识别。修改兼容处理前应检查已有数据与失败恢复路径。

`DataMigration` 使用复制、校验及同卷暂存目录移动；`copied` 阶段支持重试偏好导入，`complete` 阶段不再覆盖数据。无法识别的已有目标目录会停止处理，不得静默清空。后续格式升级同样需要明确版本、幂等行为及恢复策略。

Swift Package 测试进程默认使用临时根目录和随机偏好域。测试数据必须合成或脱敏，真实剪贴板内容不得进入日志、测试输出、截图或 Git。

### 剪贴板背景

背景视图只绘制在完整剪贴板窗口内容下方，不接收鼠标事件；毛玻璃保持为底层。透明度、缩放及九宫格位置复用缓存，静态图片复制和解码使用模块内的图片队列。窗口适配保留以太原有默认尺寸，图片比例模式最小宽度为 1120 pt（小屏受 94% 可用区域上限约束），保证列表、详情及常用内容可用；调整时保持中心并限制在当前窗口所在屏幕。

启动层在初次迁移之后执行版本化的背景补充迁移，由 `ClipboardModule` 提供校验和复制接口。已有 Aether 任一背景设置时不覆盖；图片验证并原子保存成功后才导入偏好，最后记录迁移版本。失败不会写入成功标记，保留旧图片及偏好供重试，原数据不会删除。背景设置使用 `AppEnvironment.clipboardDefaults`，图片与历史、常用内容独立。

### 常用内容

完整剪贴板窗口在顶部右侧提供常用内容按钮；点击后以约 320 pt 的原生弹出面板打开，不挤压历史列表和详情，也不依赖窗口宽度或额外的展开偏好。该区域只属于完整窗口，不新增控制中心分页或应用路由。

`QuickClipboardStorage` 将多个自动命名的常用项及其中按创建顺序排列的标题和纯文本内容保存到独立的版本化文件。新建名称依次为「常用 1」「常用 2」等，并跳过已有名称。写入使用同目录临时文件和原子替换，未知版本或损坏文件会阻止覆盖。该文件不参与剪贴板历史维护、过期清理和分类清空；内容仅通过用户明确操作删除。内容为本机明文，但错误、复制反馈和测试输出不得包含正文。

常用条目复制复用 `ClipboardStore` 的纯文本写入协调，在写入系统剪贴板后同步监控基线，因此不会把 Aether 自己的复制再次记录为历史。右栏键盘事件按当前交互区域分发；文本输入控件优先处理编辑命令，避免与历史列表的 Enter 和 Esc 行为冲突。

### Prompt 请求与持久化

Rust 核心执行 Prompt 请求体/响应协议、接口路径策略、请求代际和历史索引计划；原生 URLSession/URLComponents、Task、locale 匹配和钥匙串保留平台语义。Prompt 配置和历史文件由 Rust 校验并持有独立写入保护状态，各有版本封装，原子写入并限制本地访问权限。加载失败或遇到未知版本时保留原文件并阻止覆盖，以便恢复后重试。API Key 使用独立可注入的钥匙串存储，不进入 JSON、请求错误说明或日志。配置只保存 Key 的摘要用于一致性校验；配置写入失败会回滚 Key，即使回滚失败并重启，下次请求也会先检查摘要，避免旧服务地址误用新 Key。测试使用临时目录、模拟凭证存储和隔离 URLSession。

客户端使用非流式 Chat Completions 请求，只发送系统优化规则和本次用户输入；不附带历史，也不自动读取剪贴板。远程地址要求 HTTPS，允许本机回环 HTTP；拒绝地址中混入凭证、查询参数或片段。网络重定向不会继续携带凭证，请求设置超时，错误反馈不显示服务端原始响应正文。

编辑状态位于主线程模型中，每次请求固定输入及配置快照，并使用独立请求标识。取消、新建和选择历史使旧标识失效，即使网络晚返回也不能覆盖当前结果。收起菜单栏或切换功能分页不取消请求，模型保留输入、进度与结果；再次打开可继续使用。只有成功且完整的结果才进入历史；历史写入失败时仍保留编辑区结果并显示错误。保存开关控制后续记录，既有记录由明确删除操作管理。

## 窗口与输入协调

唯一菜单栏控制器负责紧凑面板，完整剪贴板窗口负责搜索、详情、常用文本复制和粘贴协调。打开应用界面前保存外部应用作为操作目标，切换分页时不重新捕获目标。

应用层协调用户快捷键规则与剪贴板 Carbon 内置组合；冲突时不注册内置组合，保证自定义动作优先。打开 Aether 功能的动作应交给内部路由，避免启动额外应用进程。

应用窗口操作由 `ApplicationIntent`、`ActionExecutor`、`ApplicationWindowMover` 和 `WindowMoveWorker` 协调。事件线程在真实按键、点击和滚动时同步使旧操作失效；工作区激活通知补充检查焦点变更。后台启动回调、延迟命令、窗口写入及窗口选择均检查同一个操作凭据。新建窗口命令同时检查前台进程并向指定 PID 发送，不能以固定延迟假定焦点已正确切换。

窗口 AX 访问、布局记忆和 `WindowMoveSession` 状态全部限定在 worker 的串行队列；主线程只接收可发送的快照与结果。已运行应用使用首次清单，启动或新建窗口使用最多 1.5 秒的等待和固定 120 毫秒收集期。独立超时先关闭窗口写入凭据再继续激活，完成后不再观察或移动后来出现的窗口。公开 AX 调用无法撤回应用已接受的异步操作，不应宣称能消除所有应用动画。

`WindowLayoutHistory` 按本进程分配的窗口 ID 和显示器记录布局与一次恢复批次，仅驻留内存；AX 句柄消失时清理对应记录，并限制其他应用的历史句柄缓存。记录不保存窗口标题、文档路径或正文。`ApplicationShortcutPreferences` 新增可选的最小化恢复与应用例外字段，缺失时采用原有默认行为，不需要启动时重写已有配置。

计时布局与屏幕协调由 `TimerRuntime` 管理。模块内的控制窗口辅助代码受 `timerControlWindowEnabled = false` 禁用；更改窗口入口时需要同时检查 Live Activity 行为。菜单栏面板问题应在对应控制器中解决。

## 设置

应用层持有唯一侧栏，页面标题共用 `SharedSupport.SettingsContent`。剪贴板使用原生 Form 设置行；快捷操作通过顶部分段选择器切换按键与面板、应用唤醒和快捷键。规则在同一列表中展开编辑，同时仅展开一条，不嵌入另一套设置侧栏或独立对话框。配置导入导出位于快捷操作配置区，启动数据准备失败通过通用页重试。

## 计时准确性

手动倒计时通过 `ContinuousClock` 和 `ManualCountdown` 的截止时间计算剩余时长。1 Hz 回调只刷新显示，不逐次累减；暂停保存精确剩余值，恢复重新建立截止时间。唤醒立即重新采样，UI 回调延迟与系统休眠不会丢失时间。零值、负数、非有限时长不会中断现有计时。应用退出后手动计时结束，重开为空闲；系统镜像按当前系统状态重新发现。

## 变更与验证

依赖版本在包清单与 `Package.resolved` 中固定，应用构建与模块测试使用仓库内配置。调整依赖、公共接口或数据格式时，同步检查调用方与兼容路径。

测试覆盖快捷键规则、剪贴板搜索与数据处理、常用内容持久化与检索、粘贴计划、护眼状态机、数据恢复、导航与连续时间倒计时。自动粘贴、权限及屏幕布局必须在正式安装副本中验收，详见[验收清单](Verification.md)。

## 端口模块

`PortsFeature → SharedSupport + WhatPortCore + WhatPortIOKit`。两个 WhatPort target 的固定源码在仓库内，来源版本及 MIT 声明见 NOTICE；不依赖外部源码目录。`PortsModule` 暴露摘要、详情和可见性接口，应用层通过现有 `.settings(.ports)` 路由打开唯一设置窗口。

`PortsModel` 在主线程协调两个界面的共享会话。全都不可见、窗口最小化、应用隐藏或系统休眠时取消订阅；恢复时创建新数据源，旧会话标识拒绝迟到回调。`LivePortDataSource` 使用单一 utility 串行队列执行 IOKit/SMC 读取、1秒计时器和停止释放，通知只把刷新排入该队列；快照流只缓冲最新一项。无页面可见时不初始化硬件读取器。功率曲线另用带时间戳和分段的内存窗口，最多保留60秒，缺失读数及采集会话边界不连线。不会持久化端口数据或设备序列号。

上游未公开的 IOKit 属性、SMC key 和生命周期消息仅作为当前可读取的数据源，不保证跨机型或 macOS 版本稳定。保留上游端口关联和降级逻辑；展示层不猜测缺失读数，不将累计错误转换成硬件诊断。

常用剪贴板通过借用命令字节跨度调用 Rust；Rust 持有记录及归一化比较索引，分组名称/精确标题比较的归一化来自 Foundation。正文和未修改的条目数组使用 Arc 共享，写入成功后只返回受影响分组的原生展示补丁。查询只将匹配类型、时间和分组范围交给 Rust 排名，不将正文放入日志或额外检索副本。

剪贴板历史策略通过 UUID/时间/类型/比较标志的借用数组调用 Rust，返回复用原生记录的索引计划；插入、保护裁剪、有效/过期筛选及收藏转移在核心执行。核心选择内容比较字段，原生 String/Data 比较与 RTF 文件读取维持平台行为。`abi.rs` 保存跨功能基础类型，Rust 功能模块不经其他功能模块取得通用字节或 UUID 类型。归档所有权、调度状态与完整持久化迁移仍在进行。

剪贴板调度使用 Rust 值状态机保存捕获重试、历史修订、维护代际及写入合并/清理状态。原生 Task/DispatchQueue 负责执行，归档 DTO 快照暂由 Swift 保存；系统时间和 changeCount 在调用时借用输入。资源清理由 Rust 对 canonical composition 的文件名集合规划，只在原子归档写入成功后通过原生文件接口执行。写入器的目录可注入，测试不触及真实历史或负载。

剪贴板归档的 Rust 句柄保存路径和覆盖阻止状态，按旧的无版本 history/pinnedItems/groups 格式校验，再移交读取缓冲区给原生 Codable DTO。缺省 UUID/Date/预览仍由原生生成；Rust 校验借用未转义字符串，不保留另一份正文。重复 JSON 字段沿用原生首次出现值，额外 Base64 padding 和未知字段的嵌套深度维持 Foundation 接受边界。读取失败或发现外部损坏后阻止覆盖和负载清理，明确重载有效文件才能恢复。完整记录所有权与展示 DTO 编解码仍需迁移。
